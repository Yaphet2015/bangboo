# Upgrade Pinned Runtime to pi v1.1.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (native execution — the staged worktree is sequential state, subagents cannot parallelize it). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the pinned upstream runtime from v0.87.1 to v1.1.0 so the installed `pi` (bangboo) reports `runtime 1.1.0`.

**Architecture:** Update `upstream.lock.json`, adapt the staging build order to v1.1.0's restructured workspace (`agent-core`→`agent`; `session-backends` removed; `codemode`/`mcp`/`env` added), rebase all nine patches onto the new tree, sync version-pinning tests and provenance docs.

**Tech Stack:** Node 22, tsx, vitest, git worktree staging (`.bangboo-build/upstream`).

**Spec:** Precedent commit `7ed1c67` (0.84.1→0.87.1 upgrade) + repo AGENTS.md "Upstream upgrades" rule.

## Global Constraints

- Upstream: `https://github.com/earendil-works/pi.git` tag `v1.1.0`, commit `abe508e1b89912adde45528136c3221eb69acdd7`.
- All `runtimePackages` versions must equal `codingAgent.version` = `1.1.0` (lock parser enforces).
- Bangboo distribution version: initially kept `0.1.1` per precedent, then overridden mid-session by the user to `1.1.0` (see ledger).
- Patches must pass `git apply --check` against the pinned commit (stager enforces, fail-loud).
- Staged manifest cross-checks: `bangboo`/`0.1.1`/`runtimeVersion 1.1.0`/`upstreamCommit abe508e…` + pi-compat facade mirrors `1.1.0`.
- Work on branch `upgrade/pi-1.1.0`; no git worktree isolation (npm link + `.cache` point into this directory).

## Review Focus

- **Stale runtime pin leaks into CLI:** `pi --version` must print `runtime 1.1.0` — pinned by `built-cli.test.ts` and re-checked at the end.
- **Silent patch drift:** a patch that applies but semantically misses (e.g. brand sweep target moved) — caught by `verify:brand` + integration tests.
- **Build-order gap:** new deps (`codemode`, `mcp`, `env`) not built before coding-agent → staged build fails; mirror upstream root `build` script exactly.
- **Docs lying:** README/UPSTREAM_COMPATIBILITY still saying 0.87.1 — folded into Task 5.
- **Windows/darwin test-exclusion drift:** stage script lists excluded upstream tests by path; v1.1.0 may have renamed them — checked during Task 4 only if `--upstream-test` is run; note as follow-up otherwise.
